## 工程提示词三大规范新增

### 1. Git 工作流规范（`_common/git.md` 重写）
- 分支模型：`main`(生产) ← `develop`(开发主分支，禁止直接开发)
- 功能分支：`feat-{描述/版本}` 从 develop 派生，合并回 develop
- Bug 修复：`fix-{描述/版本}` 从 develop 派生；生产热修复从 main 派生为 `fix-{版本}`
- 分支命名与版本号严格对应，合并后删除临时分支
- 保留 Conventional Commits + PR 规范

### 2. 版本管理规范（`_common/version-management.md` 新建）
- 3 段式语义化版本 `X.Y.Z`
- X=架构版本（架构调整时自增），Y=功能版本（新功能时自增），Z=修复版本（Bug修复时自增）
- 开发阶段 `-SNAPSHOT`，发布去后缀
- 分支命名与版本号对应（feat-1.2.0 → 版本 1.2.0）
- 多模块项目统一版本号

### 3. 文档管理规范（`_common/documentation.md` 新建）
- `docs/overview.md` 概要设计 + `docs/features/` 详细设计 + `docs/{version}/` 版本快照 + `docs/{version}/changelog/{序号}.md` 变更日志
- 每条 changelog 含：类型/日期/涉及文件/原始设计/变更内容/测试结果/影响范围
- **AI 开发前置验证（硬约束）**：编码前 MUST 确认版本号→验证设计文档存在→确认预期交付范围，禁止在文档缺失或版本不明时编码
- developer.md 增加"开发前置验证"节 + "版本与文档"提交前自检
